# nut-next — Project Instructions

## Project Overview

RPM packaging of the Network UPS Tools (NUT) trunk (upstream `master`) for the
[karellen/nut-next](https://copr.fedorainfracloud.org/coprs/karellen/nut-next/) COPR project.
This is **not** a PyBuilder project. The packages are `nut-next`, `nut-next-client`, `nut-next-cgi`, `nut-next-xml`,
`nut-next-devel` and (Fedora only) `nut-next-monitor`; each `Conflicts`/`Provides` its distribution `nut*` counterpart.

The packaging is the Fedora dist-git `nut` packaging adapted to the trunk. **This repository shares git history with
Fedora dist-git** (`https://src.fedoraproject.org/rpms/nut.git`); the fork point is Fedora commit `ab5d1ed`
(2026-10-07, `nut-2.8.5-9`, f44 = f43 = f45 = rawhide at the time).

The setup mirrors [karellen/smartmontools-next](https://github.com/karellen/smartmontools-next).

## Repository Layout

```
nut/                          # Git submodule -> github.com/networkupstools/nut, branch master
nut-next.spec                 # The spec (Fedora's nut.spec, renamed and adapted)
nut-2.6.5-rmpidf.patch        # Fedora patch, rebased to the trunk (upsmon removes its PID file; upsd does upstream)
nut-2.8-rhinoname.patch       # Fedora patch, rebased to the trunk (rhino driver -> nutdrv_rhino, rhbz#2367057)
libs.sh                       # Fedora helper appending library paths to include/config.h
VERSION_DEFAULT               # Generated by upstream tools/gitlog2version.sh; never edit by hand
.tito/                        # tito config; custom tagger in .tito/libs/karellen/tito/version_tagger.py
.github/workflows/update.yml  # Cron: bump submodule, regenerate VERSION_DEFAULT, tito tag, push (every 6h)
```

## Build and Release Flow

1. `update.yml` runs every 6 hours. If upstream `master` moved, it updates the submodule, regenerates
   `VERSION_DEFAULT` with `NUT_VERSION_GIT_TRUNK=HEAD NUT_VERSION_QUERY=UPDATE_FILE tools/gitlog2version.sh`, commits
   `Update <timestamp>`, runs `tito tag --accept-auto-changelog` and `git push --follow-tags`.
2. The COPR package (SCM source, `master`, tito build method) builds the pushed tag, triggered by a GitHub webhook on
   the creation of the tito tag. COPR makes a single SRPM and rebuilds it in every chroot.
3. Versioning comes from `NutVersionTagger`, which asks upstream's own helper:
   `NUT_VERSION_GIT_TRUNK=HEAD NUT_VERSION_QUERY=VER50 nut/tools/gitlog2version.sh`, i.e.
   `<last release tag>.<commits since that tag>` (`2.8.5.1602`; a release commit itself yields `X.Y.Z`).
   `NUT_VERSION_GIT_TRUNK=HEAD` makes the result depend only on the submodule commit, not on local branches.
   `Release` is reset to `1` on every version bump.
4. In the SRPM there is no `.git`, so `gitlog2version.sh` (called by `configure.ac` and `autogen.sh`) reads the
   `VERSION_DEFAULT` that `%prep` copies into the source tree.

### Rules

- **Work on `master` directly.** COPR only builds `master`, so a feature branch cannot be tested.
- **Packaging-only change without a submodule bump:** bump the release only, so the version stays and the
  tag stays unique: `tito tag --use-release=<N>`, then `git push --follow-tags origin` as tito instructs.
- **Never push more than three tags at once.** GitHub does not generate `create` events "when more than three
  tags are created at once", so COPR is never notified and does not build. Fedora's dist-git has ~140 CVS-era tags
  (`EL-*-split`, `F-*-split`, ...) pointing into the shared history; never fetch them (see below).
- A push without a new tag (e.g. a docs-only commit) does not trigger a COPR build.
- The bot commits to `master` every 6 hours; fetch/pull before committing and pushing.
- `sources` and Fedora's version-specific backport patches are intentionally not carried: the trunk contains them.

## Synchronizing with Fedora

The packaging follows the Fedora `f44` dist-git branch. Last synchronized Fedora commit: `ab5d1ed`.

The `fedora` remote is configured with `tagOpt = --no-tags` and fetches into `refs/fedora/*`. In a fresh clone:

```bash
git remote add fedora https://src.fedoraproject.org/rpms/nut.git
git config remote.fedora.tagOpt --no-tags
git config remote.fedora.fetch '+refs/heads/*:refs/fedora/*'
git fetch fedora
git log --oneline <last synced Fedora commit>..refs/fedora/f44
git merge --no-commit refs/fedora/f44
```

- `nut.spec` -> `nut-next.spec` may not be rename-detected once the tito changelog grows, in which case the merge
  reports a modify/delete conflict. Keep `nut.spec` deleted and **port Fedora's spec changes by hand**: diff the
  Fedora spec between the previous sync point and the branch tip (excluding `%changelog`) and apply the relevant
  hunks to `nut-next.spec`.
- New Fedora patches: carry them only if the trunk does not already contain the change; rebase carried patches
  onto the trunk (the build uses rpm's default patch fuzz of 0) and apply them with `-p1` inside `pushd nut`.
- Fork-specific spec parts to preserve: `%{packagename}`/`-next` naming (paths, user and data dir use
  `%{packagename}`), the `Conflicts`/`Provides` on every subpackage, Vendor/Packager, `pushd nut`, the
  `VERSION_DEFAULT` copy, `./autogen.sh` instead of `autoreconf -i`, `--with-doc=man` and its BuildRequires,
  the `monitor` bcond, and the `nut/` prefixed `%license`/`%doc` paths.
- Dropped Fedora spec lines (do not re-add): the `LIBSSL_LDFLAGS` -> `LIBSSL_LIBS` seds on `lib/libupsclient*.in`
  were no-ops on 2.8.5 and on the trunk would corrupt `@LIBSSL_LDFLAGS_RPATH@`.
- New upstream files show up as "Installed (but unpackaged)" build errors (rpm stops at the first "File not
  found", so fix those first and rebuild); add them to the right `%files` section (client-side configuration such
  as `nutauth.conf` goes to `-client` with `%attr(640,root,nut)`).

## EL Specifics

Fedora only develops the `f*`/rawhide spec; the same spec is built for EL8/9/10 (with EPEL), where it needs:

- **`monitor` bcond:** `nut-next-monitor` (NUT-Monitor, `PyNUT.py`) is built on Fedora only; EL has no
  `python3-pyqt6`. Configure gets `--with(out)-nut_monitor` explicitly.
- **`i2c` bcond:** EL8 has no `libi2c-devel`, so the I2C drivers (`asem`, `pijuice`, `hwmon_ina219`) are built
  `--without-linux_i2c` there and their man pages are conditional.
- **GPIO:** Fedora disables the GPIO driver (`%if 0%{?fedora}`); on EL it builds against libgpiod v1 (EL8) or
  v2 (EL10), hence the `generic_gpio_libgpiod.8` man page under Fedora's `%if 0%{?fedora} < 39`.
- **The `nut` user:** rpm on EL does not create the sysusers.d user before installing the files it owns (EL8/9
  have no support; EL10 runs `systemd-sysusers` from a file trigger only afterwards), so without help a fresh
  install leaves every `root:nut` file as `root:root`. `%{create_nut_user}` (`groupadd`/`useradd` with the
  sysusers values, as Fedora's epel8 branch did) runs in `%pre`, `%pre client` and `%pre cgi` on EL only.
  **Always test a fresh install, not only a replacement of the distribution `nut`**, which already created the
  user.

## Testing Changes

COPR builds only tags on `master`, so test locally before pushing:

1. Commit locally (do not push), then `tito build --test --srpm --offline -o .claude-tmp/tito`.
2. Rebuild the SRPM with mock in a representative set of chroots, e.g. `fedora-44-x86_64`,
   `alma+epel-8-x86_64`, `alma+epel-9-x86_64`, `alma+epel-10-x86_64`.
3. Install the resulting RPMs in clean podman containers of the same distributions (with EPEL on EL), both fresh
   and replacing the distribution `nut`/`nut-client`, and check: no "user/group nut does not exist" warnings,
   `id nut`, `root:nut` ownership of `/etc/ups/*.conf`, the binaries report the trunk version (`upsd -V`,
   `upsc -V`), `systemd-tmpfiles --create` works, and `rpm -V` is clean.

Use the project-local `.claude-tmp/` for scratch files.
